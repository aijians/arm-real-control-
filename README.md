## 每次任务启动前写入 PID RAM（2026-11-12）

`hardware.task_start_pid.enabled=true`：每份TXT成功解析后、相机及运动任务开始前，在主任务锁和两轴独占串口内先停止并确认双轴停稳，再通过0x42依次写角度/速度环。按2026-11-15用户指定，两轴角度环均50/0/0、速度环均500/25/0（均Kp/Ki/Kd）。同一常驻程序接收下一份任务时会重新写入，阶段重试和往返中的每段运动不重复写。空闲启动或没有有效任务时不打开串口、不写PID。

在 `config/robot.json` 的 `hardware.task_start_pid` 中选择 `"enabled": true`（加载配置中的四环PID）或 `"enabled": false`（跳过PID初始化）。关闭时不加载PID写入设备、不执行PID初始化停机或写入，日志显示 `PID RAM initialization disabled; keeping drive PID`，结果记录 `pid_initialization.status="disabled"`、`writes=[]`；相机和正常任务继续运行。省略整个 `task_start_pid` 也默认关闭。关闭只保留驱动当前PID，不会清空PID、恢复旧参数或恢复出厂值。修改配置后重新启动 `run.sh` 生效；当前仍保持开启和上述数值。

每条写入要求正确电机ID、0x42、参数ID与成功状态应答，超时/拒绝/异常立即中止任务并尝试双轴停止，保留部分写入记录，不自动回写无法确认的旧RAM值。四条全部成功才启动相机和TaskRunner；不保存ROM、不改电流环/输出限制、不使能或改变零点。`result.json.pid_initialization`记录请求值、逐条报文/应答与停止确认。`acknowledged`只表示写入应答，不冒充运行RAM独立读回或已解决全部欠角。现有0x14整组设置不能用于判定这次RAM写入是否生效。

## Free / Push 多圈绝对位置定时基线（2026-11-10）

当前 `hardware.free_timed_motion.enabled=true`，Free、Push 及 push_correction 共用该配置和执行器。Free 包括自由进场及通过 Planner.free 生成的返回路线；上述阶段均沿原关节折线细分，每轴相邻模型目标最多 `max_step_deg=0.2°`，每个后继点间隔 `period_s=0.05` 秒。保留原路径顶点、拐点及最终目标，重新生成时间；没有额外的 2°/秒路段速度限制。P0 只核对起点，之后每组向两轴各发送一条 A4 多圈绝对位置命令，驱动速度字段：Push（含 push_correction）大臂为 `push_upper_speed_deg_s=60`，小臂及 Free 两轴使用 `speed_deg_s=60`（电机轴 °/s）。

按用户确认的坐标关系，多圈电机角与当前单圈电机角直接对应，例如电机单圈160°即多圈160°。模型角仍使用既有 sign/ratio/offset 换算；不另加圈数偏移。A4 由驱动决定方向，Free / Push 不使用 A6 方向判断、方向余量或 `free_timed_direction_ambiguous` 分支。

中途不等待到位，不按跟踪误差调整目标，不做无进展恢复、偏置、领先量或主从控制。反馈继续按原20Hz查询并记录，用于失联及关节限位检查；A4 回复按状态2解析并记入诊断。每点记录计划时间、实际开始/写完时间及迟到量。迟到节点按序续发，组间至少间隔50毫秒及底层 command_rate_hz 周期，不突发追赶、不跳点；调度超过重新规划的时长加 move_timeout_margin_s 则失败。

全部点发送完后才验收终点：两轴误差≤0.3°、速度≤1°/秒，稳定0.3秒后保持1秒；角度在容差内且相对上一合格反馈变化小于0.05°时，单次速度跳变不重置计时，恢复正常后沿用原计时；同轴连续不同超速样本或角度越界仍重置，硬限异常仍失败；保留5秒整定预算。各阶段失败后先停止并确认停稳，再按最新视觉和实测关节重新规划；每阶段首次执行后最多重试3次（共4次），互不占用次数。停止未确认、主动停止、硬限异常或滑杆超调直接终止。`motion_diagnostics.execution` 记录对应阶段的 `controller=free_timed/push_timed/push_correction_timed`、`position_command=0xa4`、步长、周期、schedule、中途 feedback_samples 及截断数；保留原动作末256条格式。

Free 终点增加有限的原目标重申（2026-11-11 候选，待实机验证）：`hardware.free_timed_motion.goal_refresh.enabled=true`。仅在全部路径点已发送、尚未进入保持阶段时，逐轴观察新鲜角度及速度反馈；误差超过0.3°、速度≤1°/秒，连续0.6秒角度范围小于0.05°，才对该轴重发完全相同的最终A4目标和原速度字段，每轴最多2次。到位轴不重发；重发后重新等待该轴角度/速度新反馈，原5秒整定截止时间不延长。中途路径发送与阶段重试规则保持，Push/补推不启用这项措施。诊断中的 `goal_refresh` 记录每轴次数、时刻和重发前角差，动作的 `purpose=goal_refresh` 用于区分轨迹目标；`motion_commands_sent` 包含重发，`waypoints_dispatched` 只计路径点。它用于处理静止欠角时的终点重定位，不保证能够克服机构摩擦，也不是已确认的故障根因修复。离线验证：`PYTHONPATH=.:tests python3 -m unittest test_goal_refresh test_free_timed -q`。

终点振荡三档降速（2026-11-15）：`hardware.free_timed_motion.oscillation_downshift` 配置低/中/高三档 `speed_tiers_deg_s=[18,30,60]`（电机轴°/秒），生产启用。Free、Push、push_correction 及使用Free的观测撤离，全部路径点发送完后，用原恢复机制的幅度/趋势/反向次数判据检查每轴新鲜角度和速度反馈：1.2秒窗口、至少3次有效反向、峰峰值≥0.12°、反向有效变化≥0.04°；距固定终点≤3.5°时才参与，覆盖c10104e6中约1.7°偏离的振荡。只对振荡轴按60→30→18逐档重发相同终点A4，每降一档清空历史，观察新的反馈窗口后才允许继续降档，不改目标角或关节折线。降档只在写入成功后生效，新档位作为该轴本任务后续进场、撤离和重试的速度上限；不会自动回升，新任务创建MotorPair后重新从高档上限开始，原配置速度更低时保持更低值。

旧 withdraw 等其它阶段沿用原 A6 执行器；新增 observation_retreat 使用上述 Free A4。用户已报告 Free 实机通过；本次扩展后的 Push 尚未试动。

## 2026-11-06 当前恢复策略

下述恢复策略用于原执行器，启用定时基线的 Free / Push 不进入该策略。其它 move 阶段、两轴和两个方向共用恢复策略：先识别卡住或目标附近往复，再调速度，仍无效才调临时角目标。

卡住时常规恢复档为 18→30→60°/s（已删除45），偏置为相对原节点的绝对档位0.2→0.6→1.2°，只给异常轴。1.2°实际写出并观察0.5秒仍无进展，先将偏置归零、写回原目标，成功后才单独发送90°/s；归零未写成功不得升90。90后仍失败有限退出，不再重复加偏置。到原节点容差内会回收偏置，不要求抵达偏置位置。

无进展判定和每档观察暂设0.5秒，反馈20Hz（约10组），发送50Hz。实际响应、串口时序和方向检查可能延后发送，不保证固定0.5秒换档。整次move恢复预算仍24秒，终点±0.3°，保持1秒并容忍孤立速度跳变。抖动仍先降速、再减小角偏置；保留反向指令和反馈检查。

基础计算仍为前馈速度加角度误差，基础上限18°/s；恢复档作为当前单调段的速度下限跨节点保留。同目标/同方向已应答后，连续计算速度的细小变化不会重复刷写A6；离散 speed_tier 变更才允许重发一次。

`python3 -m unittest discover -s tests -p 'test_recovery90.py' -v` 执行纯离线虚拟驱动回归，覆盖5阶段×2轴×2方向、先归零后90、写回失败不升档、有进展不继续加档及有限退出。它不连接串口，不代表实机推杆通过。模型权重和运行数据留在板端。

# 自主推杆程序：固定场景、直线轨迹、连续录像

本版手动启动，读取固定 TXT 后自主完成推杆。开发板运行包不包含 Gazebo、STL、GEOS、A*、安全栅格生成器或开机服务。

## 启动和输入

在开发板的项目目录执行一次：

```bash
bash run.sh
```

入口不接收任务参数。之后将一条 UTF-8 自然语言指令上传到 `input/task.txt`，例如“把橙色滑杆来回推动一次”。先上传为临时文件，上传完整后改名为 `task.txt`，避免读到半个文件。固定路径只存放一份待领取任务。

模型启动时只加载一次，采用 `mini_llama.py + torch + PureBPE`，不依赖 transformers 或 tokenizers。收到有效任务后，先启动相机和录像，准备好后才接管电机。

控制台会显示任务领取、模型解析、相机启动及最终成功或失败原因。只有 `Runtime ready` 表示正在监听，不代表任务已执行；详细结果见 `output/result.json`。

程序先领取 TXT，再执行；结束时先保存 `output/result.json`，再删除本次 TXT。执行期间新上传的 TXT 留给下一次。中断后重新启动，已领取任务记录为中断并清理，不会自动重放；需要重试时重新上传。

## 两份配置

| 文件 | 内容 |
|---|---|
| `config/robot.json` | 电机和零点映射、导轨几何、端点方向、运动学与固定接触点、相机、速度、各文件路径 |
| `config/scene.json` | 工作区边界、整臂分层轮廓包络、质量块和安装件、固定中转姿态与换面通道 |

`paths.task_file/result_file/runtime_dir/model_package/scene/video_dir/python` 都支持绝对路径或相对于项目根目录的路径，与启动时所在目录无关。修改配置后重启程序。默认录像为 `videos/<task_id>.mp4`，结果中的 `video` 字段记录路径和保存状态。

整臂包络独立于实际接触点。接触点可以在配置的 `contact_segment_canonical_xy_mm` 内调整；每条新轨迹仍检查整臂包络，不能把“接触点位于白区”当作整臂安全。段外或偏离指定推面的点会被拒绝。包络与接触段在上传前准备，板端不读取 CAD 文件。

## 轨迹如何生成

自由移动只使用三种有限路线：

1. 等效接触点直接走笛卡尔直线。
2. 经固定质量块通行姿态，再走直线到预接近位。
3. 换面时，经导轨下方的固定高度通道绕到另一侧，形成最多三段直线。

路线按固定顺序检查，受阻就尝试下一种；全部受阻则返回失败，不扩展搜索栅格。每段按不超过 1.00 mm 的距离取点并逆解，电机插值点之间也用简化包络检查。采用平滑时间进度，途中不逐点等待停稳。

| 当前设置 | 值 |
|---|---|
| 向右推 | 内面固定点，沿世界 X 在销心左侧 5.00 mm 预接近 |
| 向左推 | 外面固定点，沿世界 X 在销心右侧 2.00 mm 预接近 |
| 质量块通行姿态 | 大臂 148.00°、小臂 35.00° |
| 换面通道高度 | 等效参考点 Y=135.00 mm |
| 自由移动 / 推动 / 接近速度 | 20.00 mm/s / 5.00 mm/s / 2.00 mm/s，受关节速度上限约束 |

左推预接近 5 mm 会使侧板进入当前质量块区域，所以使用 2 mm。两面的偏移量分别配置。通行姿态下，质量块的平面投影落在夹爪上下板之间，实体保持高度间隙；名义下/上间隙约为 2.98/4.20 mm，尚未实机测量验收。

推动时固定槽体上的材料点，计入销半径 4.00 mm 和面法向，使等效销心沿导轨做直线插值。内外面分别使用固定点；换面先保持实际角度，按新面重新计算当前参考点位置，不跳到理想姿态。模型小臂角直接为 ∠BAC。

未设置接触深度约束的推面沿用既有实机试验策略：不因预测擦壁而拒绝推动轨迹，保留逆解、限位、连续性和速度检查。自由移动、接近和撤离执行整臂简化包络检查。简化轮廓不能作为连续三维碰撞或实机无接触的证明。

2026-11-15 左推深接触修正：`-x` 背面选点内移至 `[128.6069763,34.5670664]` mm，并将有限接触段及法向对齐 `forearm_5_30` 的实际模型边缘，避免原参考段约0.044 mm的内陷。仍采用双轴连续轨迹、杆轴Y=155 mm和原固定X目标。`kinematics.faces.-x.minimum_stem_coverage_mm=1.0` 要求有限面两端在Y方向完整覆盖直径8 mm的杆身，并各留至少1 mm；规划密集点、下发节点及其关节插值均检查。此面启用整臂场景和沿固定轨道Y移动的目标杆检查，接触豁免仍限原推面/目标stem及原0.05 mm容差。指令抽稀弦误差从0.1收紧为接触容差的四分之一，最终定时节点再次检查；补推及其重试也使用同一检查。右推选点及其既有策略保持。

## 固定行程、遮挡识别与可靠帧验收（2026-11-15，取代下文按导轨端点定行程的部分）

起因：任务 8ddc48b7 推后蓝杆读数比按端点推出的目标多 2.69 mm 并报超调，实为前方蓝杆遮挡橙杆左半、可见中点右移所致（橙杆右边缘像素未变）；导轨端点识别的波动也已大于约 1 mm 的安装误差。

- **行程固定**：`vision.fixed_slider_limits_x_mm` 采用模型值，蓝 `[-46.56,-2.06]`、橙 `[-31.06,13.44]`（−2.06 已含 0.5 mm 预留间隙）。导轨端点仍识别，但只记在 `rail_observation.endpoint_diagnostic`，不参与任何判定。
- **识别（`vision_tools/detect_sliders.py`，地面 ground 与在轨 real 共用，差异只在 `SCENES`）**：
  - 测量带改为导轨前挡边线以上固定行（地面 20–70 px，在轨 40–80 px）。
  - 杆宽模型 `w(u)=a+b·u` 由录像离线拟合，工具为 `vision_tools/eval_slider_detection.py calibrate-width`。
  - 蓝杆固定在前；后杆近侧被前杆遮挡时，改用远侧边缘减半个模型杆宽（`rod_band_far_edge_width_model`）。
  - 每根杆输出 `reliable/reasons/measurement`。两侧可见但宽度与模型差超过 20%，或远侧可见宽度低于下限（远侧也被机械臂挡住），判为不可靠。
  - 在轨 ROI 上沿改为 80，以覆盖左端蓝杆。
- **视觉层**：`reliability` 合并识别层结果与“读数越过固定止挡超过 `beyond_stop_tolerance_mm`（2.5）”检查。2.5 mm 用于容纳近似外参下的系统偏差：地面左止挡蓝杆读数约 −47.9～−48.7。
- **初始确认**：连续 3 帧两色均可靠、两杆位置波动 ≤ 1 mm 才冻结目标；任务起点也按 2.5 mm 止挡容差检查。
- **验收（`control/tasks.py`）**：
  - 只有可靠帧计入；另一根杆相对初始读数漂移超过 `stationary_drift_mm`（1.0）也判不可靠。
  - 不可靠帧最多补取 `unreliable_extra_samples`（3）帧；仍不可靠时报 `verification_unreliable`，不再推。
  - `verification.force_pass_unreliable=true` 时强制通过并进入下一阶段，结果标 `forced`，状态中目标杆位置取任务目标。
  - 端点目标使用 `endpoint_window_mm=[2.5,1.0]`（欠推/越过余量）；越过余量的读数判为不可靠而非超调。中间目标仍用 `tolerance_mm=0.5`。
- **到位与补推**：
  - 端点目标的模型推头 X 落在 `planning.arrival_window_mm`（±2.5）内时，settle/hold 超时、no_progress 等到位类电机错误被吸收，记于 `arrival`，之后撤离观测。
  - 只有可靠视觉确认欠推才补推，补推后的模型推头不越过 −2.06；若推头已到终点则报 `push_correction_model_target_reached`。

## 任务与视觉闭环

支持定向距离、推到指定另一端、往返三类任务。任务开始时从实际图像检测银色导轨板外边缘的两个端点，换算后生成本任务范围；不再使用模型固定全局 `x_limits_mm/end_x_mm`，也不再使用两销摆在模型端点时拟合的 `rail_x_correction`。距离超行程时截断；推到另一端只按颜色读取方向，蓝向右、橙／黄向左；一次往返从任务开始的位置出发，到另一端后返回该位置。

`vision.rail_geometry` 保存固定几何：外板实测总长 `length_mm=78.80`、外边缘到外端销中心 `center_inset_mm=9.00`、板前沿相对销轴 `edge_y_offset_mm=-8.00`，以及既有模型的占位端预留 `occupied_end_clearance_mm=15.50`。最后一项为另一载块的15.00 mm宽度加0.50 mm间隙，保留既有两色端点含义，不是执行器对两销距离的动态碰撞检查。

设视觉换算的板左右边缘为 L、R，则蓝销范围为 `[L+9.00, R-9.00-15.50]`，橙销范围为 `[L+9.00+15.50, R-9.00]`。首次观测决定的范围、目标与往返起点在本任务内保持固定；以后新帧用于验收销位置。端点被遮挡或落在识别区边界时返回空端点，不用识别区边界冒充实物端点；首次缺失范围则拒绝规划。运动后端点被机械臂遮挡时，仍可识别销位置并按任务初始目标验收。

初始范围必须连续三张新帧有效，且两端换算范围的最大波动不超过1.00 mm；默认最多读取四次，缺失或不稳定会清空连续计数，停止未确认则立即退出。只在确认后冻结最后一帧范围，后续重试不移动任务目标。两色位置与名义行程的一致性容差 `vision.rail_geometry.limit_position_tolerance_mm` 默认2.50 mm，用于容纳近似标定与近端销轴识别残差；这不扩大运动范围，也不改变所选滑杆起点检查的0.50 mm容差。跨度仍须在72～90 mm内。`initial_limits_confirmation` 保存初始帧确认记录；每帧的 `rail_observation` 记录端点像素、肩轴系端点、跨度、候选行程、各色超界量及具体拒绝原因，耗尽后保持停止并报告失败。

检测输出保留原 `rail_line`（用于分割及兼容原合并图），新增 `rail_endpoints_px`。单独脚本预览会标注实测 L/R。导轨长边与销轴处于不同 Y 平面：板前沿使用肩轴系 Y=147.00 mm（全局173.30 mm），销轴使用 Y=155.00 mm（全局181.30 mm）。不能把图像中位于同一条参考线上的两类点当成世界中同一平面。

每个任务只打开一次相机。单条视频流分支保存录像和提供最新帧；识别直接读取内存图像，不写临时照片。录像覆盖进场、推动、验收、换面、重试和返回。推动中不根据视觉改轨迹；停止后等待新帧验收，默认连续三个不同帧在 0.50 mm 容差内。帧时间表示接收时间，曝光与链路延迟仍需实测。

环境读取、Free进场、Push、每个补推、旧撤离和返回均保留独立的3次重试机会（首次加3次，共4次）。Push结束或可恢复失败后，先停稳，再从实测关节规划观测撤离；撤离后再次停稳、核对实测姿态，才读取新帧验收。重试中若进场或撤离尚未完成，先完成安全观测撤离再取图。已到目标则直接通过，超调不反推；仍未到目标则从新视觉及实测姿态重新Free进场，再执行Push或原定补推。重试中的Free、观测撤离、视觉失败均消耗当前阶段机会，不额外嵌套重试。补推仍最多3步、每步1.00 mm、累计3.00 mm；同一步重试固定原终点，不增加距离预算，参考点保留撤离前的实测接触姿态。旧撤离重试仍保持原终点。全部重试用尽后结束任务；主动停止、停止未确认和硬限异常不自动恢复。`stage_attempts`逐阶段记录0～3次尝试、失败原因、停稳确认及起始状态，终端输出`retry 阶段 n/3`。任务成功后按原流程返回配置的168.00°/4.00°（模型角）。录像以 EOS 正常收尾；录像保存失败会在结果中报告。

## 开发板依赖与验证边界

依赖 Python 3.10+、NumPy、OpenCV、torch，以及板端现有 GI/GStreamer 和 `mpph264enc/h264parse/mp4mux/videoconvert/appsink`。不需要 ROS、编译器或 GEOS。两路 RS485 为大臂 `/dev/ttyS1`、ID1，小臂 `/dev/ttyS4`、ID2，115200、8N1。相机默认 `/dev/video31`、1920×1080、30 fps；设备与相机配置均可修改。

两路电机各自保留至少 5 ms 的发送间隔，给半双工 RS485 留出回包时间；角度和状态查询先发两路角度，再发两路状态。查询丢包时在原总超时内重试。停止也遵守回包间隔，避免停止帧被干扰；这不是硬实时停止时延保证。

如果结果为 `initial_stop_not_confirmed` / `joint_feedback_stale`，查看 `stop.errors[].details` 中的电机、串口和缺失反馈类型。板端对照试验确认：原先同口连续发送 94/9C 会破坏回包；修复后连续 30 次双轴读取全部成功。没有通过放宽停止确认来绕过故障。

`docs/TEST_RESULTS.txt` 是离线单元测试结果，`docs/PLANNING_CHECK.json` 是完整任务角度流程与本机规划耗时。后者使用理想到位反馈，包含往返、中间起点和 ±0.50 mm 坐标偏移，不代表物理动作成功。`docs/MIGRATION_TEST.json` 记录目录迁移检查。
