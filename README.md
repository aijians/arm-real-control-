## Free / Push 多圈绝对位置定时基线（2026-11-10）

当前 `hardware.free_timed_motion.enabled=true`，Free、Push 及 push_correction 共用该配置和执行器。Free 包括自由进场及通过 Planner.free 生成的返回路线；上述阶段均沿原关节折线细分，每轴相邻模型目标最多 `max_step_deg=0.2°`，每个后继点间隔 `period_s=0.05` 秒。保留原路径顶点、拐点及最终目标，重新生成时间；没有额外的 2°/秒路段速度限制。P0 只核对起点，之后每组向两轴各发送一条 A4 多圈绝对位置命令，驱动速度字段：Push（含 push_correction）大臂为 `push_upper_speed_deg_s=60`，小臂及 Free 两轴使用 `speed_deg_s=60`（电机轴 °/s）。

按用户确认的坐标关系，多圈电机角与当前单圈电机角直接对应，例如电机单圈160°即多圈160°。模型角仍使用既有 sign/ratio/offset 换算；不另加圈数偏移。A4 由驱动决定方向，Free / Push 不使用 A6 方向判断、方向余量或 `free_timed_direction_ambiguous` 分支。

中途不等待到位，不按跟踪误差调整速度或目标，不做无进展恢复、偏置、重发、领先量或主从控制。反馈继续按原20Hz查询并记录，用于失联及关节限位检查；A4 回复按状态2解析并记入诊断。每点记录计划时间、实际开始/写完时间及迟到量。迟到节点按序续发，组间至少间隔50毫秒及底层 command_rate_hz 周期，不突发追赶、不跳点；调度超过重新规划的时长加 move_timeout_margin_s 则失败。

全部点发送完后才验收终点：两轴误差≤0.3°、速度≤1°/秒，稳定0.3秒后保持1秒；角度在容差内且相对上一合格反馈变化小于0.05°时，单次速度跳变不重置计时，恢复正常后沿用原计时；同轴连续不同超速样本或角度越界仍重置，硬限异常仍失败；保留5秒整定预算。各阶段失败后先停止并确认停稳，再按最新视觉和实测关节重新规划；每阶段首次执行后最多重试3次（共4次），互不占用次数。停止未确认、主动停止、硬限异常或滑杆超调直接终止。`motion_diagnostics.execution` 记录对应阶段的 `controller=free_timed/push_timed/push_correction_timed`、`position_command=0xa4`、步长、周期、schedule、中途 feedback_samples 及截断数；保留原动作末256条格式。

Free 终点增加有限的原目标重申（2026-11-11 候选，待实机验证）：`hardware.free_timed_motion.goal_refresh.enabled=true`。仅在全部路径点已发送、尚未进入保持阶段时，逐轴观察新鲜角度及速度反馈；误差超过0.3°、速度≤1°/秒，连续0.6秒角度范围小于0.05°，才对该轴重发完全相同的最终A4目标和原速度字段，每轴最多2次。到位轴不重发；重发后重新等待该轴角度/速度新反馈，原5秒整定截止时间不延长。中途路径发送与阶段重试规则保持，Push/补推不启用这项措施。诊断中的 `goal_refresh` 记录每轴次数、时刻和重发前角差，动作的 `purpose=goal_refresh` 用于区分轨迹目标；`motion_commands_sent` 包含重发，`waypoints_dispatched` 只计路径点。它用于处理静止欠角时的终点重定位，不保证能够克服机构摩擦，也不是已确认的故障根因修复。离线验证：`PYTHONPATH=.:tests python3 -m unittest test_goal_refresh test_free_timed -q`。

撤离等其它阶段沿用原 A6 执行器。用户已报告 Free 实机通过；本次扩展后的 Push 尚未试动。

离线验证：`PYTHONPATH=.:tests python3 -m unittest discover -s tests -p test_free_timed.py -v`。旧版完整测试集的已知失败见交接记录，不能把虚拟回放写成实机通过。

## 2026-11-06 当前恢复策略

下述恢复策略用于原执行器，启用定时基线的 Free / Push 不进入该策略。其它 move 阶段、两轴和两个方向共用恢复策略：先识别卡住或目标附近往复，再调速度，仍无效才调临时角目标。

卡住时常规恢复档为 18→30→60°/s（已删除45），偏置为相对原节点的绝对档位0.2→0.6→1.2°，只给异常轴。1.2°实际写出并观察0.5秒仍无进展，先将偏置归零、写回原目标，成功后才单独发送90°/s；归零未写成功不得升90。90后仍失败有限退出，不再重复加偏置。到原节点容差内会回收偏置，不要求抵达偏置位置。

无进展判定和每档观察暂设0.5秒，反馈20Hz（约10组），发送50Hz。实际响应、串口时序和方向检查可能延后发送，不保证固定0.5秒换档。整次move恢复预算仍24秒，终点±0.3°，保持1秒并容忍孤立速度跳变。抖动仍先降速、再减小角偏置；保留反向指令和反馈检查。

基础计算仍为前馈速度加角度误差，基础上限18°/s；恢复档作为当前单调段的速度下限跨节点保留。同目标/同方向已应答后，连续计算速度的细小变化不会重复刷写A6；离散 speed_tier 变更才允许重发一次。

`python3 -m unittest discover -s tests -p 'test_recovery90.py' -v` 执行纯离线虚拟驱动回归，覆盖5阶段×2轴×2方向、先归零后90、写回失败不升档、有进展不继续加档及有限退出。它不连接串口，不代表实机推杆通过。模型权重和运行数据留在板端。

# 自主推杆程序：固定场景、直线轨迹、连续录像

本版手动启动，读取固定 TXT 后自主完成推杆。开发板运行包不包含 Gazebo、STL、GEOS、A*、安全栅格生成器或开机服务。

## 启动和输入

在开发板的项目目录执行一次：

```bash
bash run.sh
```

入口不接收任务参数。之后将一条 UTF-8 自然语言指令上传到 `input/task.txt`，例如“把橙色滑杆来回推动一次”。先上传为临时文件，上传完整后改名为 `task.txt`，避免读到半个文件。固定路径只存放一份待领取任务。

模型启动时只加载一次，采用 `mini_llama.py + torch + PureBPE`，不依赖 transformers 或 tokenizers。收到有效任务后，先启动相机和录像，准备好后才接管电机。

控制台会显示任务领取、模型解析、相机启动及最终成功或失败原因。只有 `Runtime ready` 表示正在监听，不代表任务已执行；详细结果见 `output/result.json`。

程序先领取 TXT，再执行；结束时先保存 `output/result.json`，再删除本次 TXT。执行期间新上传的 TXT 留给下一次。中断后重新启动，已领取任务记录为中断并清理，不会自动重放；需要重试时重新上传。

## 两份配置

| 文件 | 内容 |
|---|---|
| `config/robot.json` | 电机和零点映射、导轨几何、端点方向、运动学与固定接触点、相机、速度、各文件路径 |
| `config/scene.json` | 工作区边界、整臂分层轮廓包络、质量块和安装件、固定中转姿态与换面通道 |

整臂包络独立于实际接触点。接触点可以在配置的 `contact_segment_canonical_xy_mm` 内调整；每条新轨迹仍检查整臂包络，不能把“接触点位于白区”当作整臂安全。段外或偏离指定推面的点会被拒绝。包络与接触段在上传前准备，板端不读取 CAD 文件。

## 轨迹如何生成

自由移动只使用三种有限路线：

1. 等效接触点直接走笛卡尔直线。
2. 经固定质量块通行姿态，再走直线到预接近位。
3. 换面时，经导轨下方的固定高度通道绕到另一侧，形成最多三段直线。

路线按固定顺序检查，受阻就尝试下一种；全部受阻则返回失败，不扩展搜索栅格。每段按不超过 1.00 mm 的距离取点并逆解，电机插值点之间也用简化包络检查。采用平滑时间进度，途中不逐点等待停稳。

| 当前设置 | 值 |
|---|---|
| 向右推 | 内面固定点，沿世界 X 在销心左侧 5.00 mm 预接近 |
| 向左推 | 外面固定点，沿世界 X 在销心右侧 2.00 mm 预接近 |
| 质量块通行姿态 | 大臂 148.00°、小臂 35.00° |
| 换面通道高度 | 等效参考点 Y=135.00 mm |
| 自由移动 / 推动 / 接近速度 | 20.00 mm/s / 5.00 mm/s / 2.00 mm/s，受关节速度上限约束 |

左推预接近 5 mm 会使侧板进入当前质量块区域，所以使用 2 mm。两面的偏移量分别配置。通行姿态下，质量块的平面投影落在夹爪上下板之间，实体保持高度间隙；名义下/上间隙约为 2.98/4.20 mm，尚未实机测量验收。

推动时固定槽体上的材料点，计入销半径 4.00 mm 和面法向，使等效销心沿导轨做直线插值。内外面分别使用固定点；换面先保持实际角度，按新面重新计算当前参考点位置，不跳到理想姿态。模型小臂角直接为 ∠BAC。

推动段沿用约定的实机试验策略：不因预测擦壁而拒绝推动轨迹，但保留逆解、限位、连续性和速度检查。自由移动、接近和撤离执行整臂简化包络检查。简化轮廓不能作为连续三维碰撞或实机无接触的证明。

## 任务与视觉闭环

支持定向距离、推到指定另一端、往返三类任务。任务开始时从实际图像检测银色导轨板外边缘的两个端点，换算后生成本任务范围；不再使用模型固定全局 `x_limits_mm/end_x_mm`，也不再使用两销摆在模型端点时拟合的 `rail_x_correction`。距离超行程时截断；推到另一端只按颜色读取方向，蓝向右、橙／黄向左；一次往返从任务开始的位置出发，到另一端后返回该位置。

`vision.rail_geometry` 保存固定几何：外板实测总长 `length_mm=78.80`、外边缘到外端销中心 `center_inset_mm=9.00`、板前沿相对销轴 `edge_y_offset_mm=-8.00`，以及既有模型的占位端预留 `occupied_end_clearance_mm=15.50`。最后一项为另一载块的15.00 mm宽度加0.50 mm间隙，保留既有两色端点含义，不是执行器对两销距离的动态碰撞检查。

设视觉换算的板左右边缘为 L、R，则蓝销范围为 `[L+9.00, R-9.00-15.50]`，橙销范围为 `[L+9.00+15.50, R-9.00]`。首次观测决定的范围、目标与往返起点在本任务内保持固定；以后新帧用于验收销位置。端点被遮挡或落在识别区边界时返回空端点，不用识别区边界冒充实物端点；首次缺失范围则拒绝规划。运动后端点被机械臂遮挡时，仍可识别销位置并按任务初始目标验收。

检测输出保留原 `rail_line`（用于分割及兼容原合并图），新增 `rail_endpoints_px`。单独脚本预览会标注实测 L/R。导轨长边与销轴处于不同 Y 平面：板前沿使用肩轴系 Y=147.00 mm（全局173.30 mm），销轴使用 Y=155.00 mm（全局181.30 mm）。不能把图像中位于同一条参考线上的两类点当成世界中同一平面。

每个任务只打开一次相机。单条视频流分支保存录像和提供最新帧；识别直接读取内存图像，不写临时照片。录像覆盖进场、推动、验收、换面、重试和返回。推动中不根据视觉改轨迹；停止后等待新帧验收，默认连续三个不同帧在 0.50 mm 容差内。帧时间表示接收时间，曝光与链路延迟仍需实测。

环境读取、Free进场、Push、每个补推、撤离和返回均有独立的3次重试机会（首次加3次，共4次）。失败后确认两轴停稳，重新获取视觉及关节反馈，再规划当前阶段；Push失败后的每次重试会重新读取相机新帧与实测关节，先验收滑杆；已到目标则直接通过，超调不反推。仍未到目标时重新规划并执行Free进场，Free成功后再规划执行Push。重试中的Free失败也消耗这次Push重试机会，整套重新进场最多3次，不额外嵌套重试。撤离、返回失败仍只重试自身阶段。补推仍最多3步、每步1.00 mm、累计3.00 mm；同一步重试固定原终点，不增加距离预算。撤离重试同样保持原终点。全部重试用尽后结束任务；主动停止、停止未确认和硬限异常不自动恢复。`stage_attempts`逐阶段记录0～3次尝试、失败原因、停稳确认及起始状态，终端输出`retry 阶段 n/3`。任务结束后返回配置的170.00°/4.00°。录像以 EOS 正常收尾；录像保存失败会在结果中报告。

视觉保留稳定的销轴识别和当前名义相机标定：黄色对应橙杆，全局 XY 减 `(189.30,26.30)` 得肩轴坐标。板边缘与销轴分别按各自 Y 平面求交，均不再套用旧的两销 affine 修正。

实测总长78.80 mm用于诊断，不据此强行缩放或把销吸附到目标。结果的 `initial_state.raw.rail` 记录原始边缘像素、板边世界坐标、实际换算板长、实测总长与差值；`slider_limits_x_mm` 记录由此生成的任务范围。

## 2026-11-03 有限补推试验

本次修改基线是重新从开发板 `/root/space_experiment/arm_real_control` 读取的现版，不使用本地旧控制代码。进场余量原本已经存在：右推时在销左侧5.00 mm，左推时在销右侧2.00 mm，本次保持。`push_correction` 集中配置步长、次数、累计距离、速度与有效进展阈值。补推是接触参考点的有限延伸，不能改变任务实际目标或把卡住当成功。成功补推后，撤离先退回累计延伸量再退原进场间隙；仅目标销柱与接触面的有限重叠可以在此撤离阶段豁免，其它部件、其它销、障碍和后续自由运动仍检查。

实机预检发现蓝销已在中间，槽左边缘识别受遮挡变化，使端点目标相对旧录像偏移约11 mm。因此本轮先使用正常TXT入口执行橙销向左10 mm／向右10 mm的短程试验，分别记录两种推面与补推表现。端点识别稳定性没有通过本轮修改解决，短程通过也不代表全行程或三类任务已稳定完成。
