# 相机内参和已知世界棋盘外参标定

在开发板原 `/opt/camera_calibration_20261105` 程序基础上扩展。保留原内参自动/手动采样、清晰度/停稳/重复姿态筛选、九宫格覆盖、后台标定、原图/去畸变预览、YAML/JSON下载和历史组文件。支持显式选择 video22 或 video31，不自动打开相机、不操作电机、不修改机械臂配置。

## 启动与访问

已有服务仍为 `camera-calibration.service`，原启动设置仍默认video22、127.0.0.1:8080。开发板执行：

```bash
systemctl start camera-calibration.service
```

电脑建立隧道：

```bash
ssh -N -L 18080:127.0.0.1:8080 root@192.168.21.100
```

访问 `http://127.0.0.1:18080`，先在网页选择 **当前机械臂 /dev/video31**。换相机前停止取流；换相机会新建空组、清除已加载内参，但磁盘历史不删除。当前硬件映射：video22=m00_b_imx415 3-001a/rkisp0；video31=m01_f_imx415 4-001a/rkisp1。

也可手动启动（不要与服务占同端口）：

```bash
cd /opt/camera_calibration_20261105
/usr/bin/python3 app.py --device /dev/video31 --port 8080 --output /var/lib/camera-calibration-video31
```

程序仅启动网页，点击“启动相机”才取流。网页或隧道关闭不会自动停止相机，请完成后点击“停止取流”。`systemctl stop camera-calibration.service` 停服务会释放相机；程序重启后内存中的组选择不恢复，磁盘文件保留。网页所示本组目录是实际保存位置；切换设备时使用独立新组，未改原服务的数据根目录。

## 6mm小棋盘与内参

网页可下载 `patterns/checkerboard_6mm_8x6_A4.pdf`。A4选择“实际大小/100%”，关闭“适合页面”；测量横线60mm、竖线30mm、棋盘宽54mm高42mm。9×7方格，每格6mm，**内角点8列×6行**；含白边裁切卡片70×58mm。贴平在硬板上并保留白边和O/U/V标识，方格边长填打印后实测值。横纵比例不一致应重新打印，不能仅改一个格距补偿。

先复装镜头到最终位置、调焦固定，再对当前video31、1920×1080原图模式标定。内参采集时相机固定、棋盘在多位置/远近/倾斜姿态停稳约1秒。15张为最低计算数，建议25～40张，九宫格至少覆盖5区；默认自动采到40张暂停。棋盘需完整清晰，6mm格在较远处会太小，可移近但保持清晰和完整。程序保留半尺寸检测，并增加原始分辨率检测回退。打印尺寸正确不等于相机标定精度保证。

点击“开始标定”后检查总体/每图RMS与去畸变直线，下载内参JSON/YAML。RMS>1px、单图>2px会提示检查；通过仅为像素初筛。原始PNG、samples.json、calibration.json/YAML保存在本组目录。若需补拍，停止取流后重新启动同组；修改规格需新建一组。同型号不同实体相机的内参不能直接混用。

## 用已有内参求世界外参

1. 网页选择正确相机。点击“使用本组内参”，或上传该相机原程序/本程序导出的**内参JSON**。严格核对device、sensor、1920×1080、sensor_raw及五参数D；拒绝其他实体、转正图、去畸变图或不同分辨率。旧JSON没写像素方向时仅按旧程序的sensor_raw约定接收。YAML原下载功能保留，但本次导入入口使用JSON完整报告以核对实体信息。
2. 将棋盘固定在世界位置已知处。需知道位置和方向，不能只量板中心。选择8×6内角点、实测约6mm格距，启动相机。此时不需要收集15张新内参样本；自动采样可关闭。
3. 点击“拍摄外参图”。它固定当前新鲜、停稳、完整清晰的原图，单独建`world_pose_<随机号>`目录；不污染内参样本。画面为原始方向，倒装相机的图会颠倒。
4. 在固定图上依次点**O、U、V**三个内角点，按纸上标签对应：O是距棋盘黑白区域左/上边各一格的内角点；U是其同一行最后的内角点；V是其同一列最后的内角点。O→U跨度7格=42mm，O→V跨度5格=30mm。外侧纸边、黑格中心和棋盘最外角均不是这三个点。手工选择明确消除180°角点编号歧义，不凭检测编号猜世界方向。
5. 填写这三点各自的世界XYZ(mm)。当前世界仅X反向、Y/Z不变，选择“左手”；原机械臂局部坐标系不变。也支持明确选择右手世界。检查导轨轴心Y=181.5和挡边Y=172.5（后者沿用轴心前9mm，需核实），两值只附于导出配置，不参与棋盘位姿求解。
6. 点击“计算世界外参”。程序在右手棋盘系用固定K/D做IPPE，再通过三点定义的正交基变换到用户世界系，输出世界光心C、R_world_from_camera、光轴、全部角点观测/重投影及两种图像方向的配置。允许的小量测差仅做正交化，不对棋盘拉伸/剪切；报告记录输入长度与名义长度、夹角。
7. 平面棋盘可能给两个近似候选。页面列出各自RMS、最大误差、光心和光轴；若接近会明确提示。换一个**已知世界摆放位置**重新拍摄，比较所得C/R并用独立点检查，不能只凭小RMS认定毫米精度。网页显示光心XYZ是mm，R是相机坐标→世界坐标，**tvec不是世界光心**。
8. 选择候选并点击“导出选中候选”：下载`camera_world_scene_upright.json`（原图先转180一次后的K/D/R）或`camera_world_sensor_raw.json`（原图K/D/R），以及完整报告/原图。两份C相同；主点以W−1−cx、H−1−cy换算，p1/p2反号。不自动写robot.json、不自动激活外参，未独立验证的候选标记为approximate/reprojection_only。

原图→转正版本仅适用于本设备当前180°倒装约定。采集全程用原始图和原始K/D，无应用裁剪/翻转，去畸变预览不参与外参角点求解。左手world导出R为正交矩阵det=-1，不能误当右手物理旋转传给要求det=+1的接口；PnP本身始终在右手棋盘系求解。

每次固定图像保存：sensor_raw.png、corners.jpg、capture.json（角点、内参快照、设备和原图SHA）。计算保存extrinsics.json；选定后保存两份camera_world JSON和selection.json。时间为板端UTC，可能不准，随机编号防覆盖。新图/错误重算会使当前下载入口失效，旧文件留作证据。

## 离线检查

本地或板端程序目录执行，不打开相机或电机：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. /usr/bin/python3 -s -m unittest discover -s tests -v
```

覆盖原5项内参回归、已知左右手世界位姿恢复、四种角点顺序、原图/180°投影一致与机械臂配置格式、跨相机拒绝、错误世界坐标/对应关系、冻结证据/导出失效和设备切换。合成数据检查不替代打印、实际video31内参、舱内三点量测和世界精度验证。
