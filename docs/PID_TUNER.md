# 大臂 / 小臂 PID 浏览器调参台：厂家 V2.35 适配版

## 启动与退出

开发板上先退出机械臂主控制程序，支撑所选关节，清空运动范围，再执行：

```bash
cd /root/space_experiment/arm_real_control
bash run_pid_tuner.sh --real --pause-sal --host 0.0.0.0 --port 8765
```

电脑打开终端打印的完整链接，将其中 `<开发板IP>` 换成 `192.168.21.100`，保留全部 `#token=...`。每次启动口令不同；升级后强制刷新浏览器。若端口已占用，先退出旧调参服务，不要重复启动。

`--pause-sal` 临时暂停已确认的 `/userdata/satellware/bin/sal` 扫描进程，不关闭整个 initrun.service、不永久更改开机服务。若暂停时它持有电机串口，会恢复并等待空闲窗口。退出时先停稳电机、释放串口，再恢复本工具暂停的 sal；原先由别人暂停的进程不擅自恢复。独立守护进程会在服务异常退出（包括 SIGKILL）后恢复 sal，此机制不等于电机急停。此选项仅允许实机模式。

前台 `Ctrl+C` 正常退出。这个隔离只覆盖调参服务运行期间；正常机械臂任务也必须独占串口，不能同时让 sal 扫描电机 UART。

默认选择大臂 `upper`（`/dev/ttyS1`、ID1、115200）；调节小臂时使用 `--axis lower`，自动选择配置中的 `/dev/ttyS4`、ID2，并加载小臂自己的 sign、ratio、offset 和有效角度限位。按关节名称选择，不依赖配置中的排列顺序。不要用大臂模式覆盖串口和 ID 来代替选择小臂。

小臂实机启动：

```bash
bash run_pid_tuner.sh --axis lower --real --pause-sal --host 0.0.0.0 --port 8765
```

需要临时暂停 sal 时，隔离逻辑使用所选关节的串口；退出时恢复。`--device` 和 `--motor-id` 只覆盖所选关节的连接参数，不修改 robot.json。

每次运行只调节一个关节。切换时先停止、断开并用 Ctrl+C 退出工具，再以 `--axis upper` 或 `--axis lower` 重启。页面标题、关节标识、串口和 ID 显示当前选择；JSON 连接信息和 CSV 的 axis/motor_id 列也保留关节身份。小臂模式隐藏大臂的 PID 参考按钮，应以本次读取到的小臂参数为起点逐项调整。

小臂纯模拟界面：

```bash
bash run_pid_tuner.sh --axis lower --demo --host 0.0.0.0 --port 8765
```

模拟初始小臂角为 45°，仅用于检查界面与操作流程，不代表真实调参效果。

大臂纯模拟界面：

```bash
bash run_pid_tuner.sh --demo --host 0.0.0.0 --port 8766
```

## 使用流程

1. 点击“连接电机”，仅读取、备份，不使能、不运动、不写参数。原始大臂整组设置中角度 PID 为 50/0/0，速度 PID 为 300/10/0（Kp/Ki/Kd）。若之前改过，以本次整组设置读回为准；它不是已确认的运行 RAM 快照。
2. 下载“会话 JSON”。自动备份路径为 `runtime/pid_tuner/real/<session_id>.json`，含原始104字节设置；不会覆盖之前会话。
3. 每次只改一个值，点击该环“写入 RAM”。程序先停止并确认停稳，再发0x42，严格检查参数编号与成功标志。成功显示琥珀色“RAM 已应答 · 运行值未读回”，单独记录请求目标、应答与0x14整组设置读回。整组设置仍返回旧值，不再被误报为RAM写入失败，也不会覆盖已应答目标。
4. RAM成功应答不等于独立读回运行参数。需由操作者决定是否小幅试转：目标先取当前位置，再只改变2°，速度先固定18°/s。单次位移限制10°、速度限制60°/s，并遵守所选关节的项目限位。电机关闭时需手动使能，不自动使能。点击“试转并保持观察”后，确认本次起点、绝对目标、速度和保持规则。
5. 到位后不立即发停止：先连续0.3秒满足误差±0.2°、速度≤1°/s，进入保持观察；连续3秒满足条件后显示“验证成功”，继续保持同一目标。未通过验证的保持阶段最多30秒；通过后持续保持，不再因30秒到期而停止。成功保持中可编辑目标和速度，点击“前往下一角度”，无需先停输出；每个新目标重新做3秒验证。程序按最新实测角度重新检查单次≤10°、配置行程和速度限值。运行中或验证未通过时禁止新目标，所有保持阶段都禁止读取参数、写入、保存和恢复；停止始终可用。看角度、速度、电压、温度、MS输出raw曲线；有抖动、异常噪声、温升或推不动时先停止、回退最近修改，不要长时间堵转。保持阶段普通偏离采用持续性判断；明显偏离、故障、浏览器心跳中断3秒、验证期限到或断开连接时仍会尝试停止。
6. 满意后点击“保存整组 ROM”。确认框显示每环实际将保存的数值：优先使用本会话0x42已成功应答的目标，未修改的环使用整组设置读回，不使用尚未下发的表单。服务端重新读取104字节设置快照，保留其他字段，叠加已应答的PID目标构造整组0x15，并核对与确认框目标一致；存在未知PID修改或其他字段偏离可信快照时拒绝保存。可信快照初始为连接备份，之后仅在本工具整组保存并读回一致后更新；原始备份始终保留。
7. 保存命令应答后用0x14逐字节核对整组数据。应答及数据一致仍不能证明断电持久；按型号要求手动重新上电后再读回核验。重上电前停止并支撑所选关节。

“恢复备份”将连接时整组设置快照中的该环PID重新下发RAM，不自动改ROM，也不宣称恢复了连接前无法独立读回的运行RAM。更早原始值可查 `output/motor_pid_original_backup.json`，它与本次连接备份不同。

### 为什么成功后还要保持？停止后回位是否算失败？

例如从154°前往152°：原来程序到位后就发送0x81停止。如果停止后输出归零，机械臂受重力或弹性回到154°附近，这不是程序发送了“返回154°”，也不能据此判断到位前的PID效果。现在分开记录：`running`前往152° → `holding`在152°附近连续观察 → `trial_outcome=passed`验证成功且持续保持。此时可直接发送下一目标150°，不会先发0x81；上一目标的结果存入`previous_trial`与会话事件，新目标从最新实测位置开始重新验证。手动停止、断开连接或保护触发后才进入`phase=stopped`，停止不会擦除已取得的试验结论。

独立“本次试验结果”区域保留起始角、目标、停止前试验误差、保持峰值误差与停止原因。实时反馈显示停止后的实际位置，两者不要混用。保持期间确认持续异常或明显偏离会更新试验结论为失败；3秒验证只说明采样点满足到位和速度条件，不能证明没有高频细抖、所有负载下稳定或电机运行RAM已经独立读回。成功后没有30秒自动停止，请留在页面观察，页面心跳必须持续正常。停止前支撑所选关节；停止后保持输出可能解除，机械臂可能回位。

### V3.4：到位标准与停止保护分开

到位验证仍要求位置误差±0.2°、速度≤1°/s连续3秒。保持中一次短暂超出不会立即停止，而是显示“保持波动观察中”；连续至少3个采样且持续至少0.5秒仍未恢复，才停止。恢复到允许范围会清除当前观察，不把多个相互分开的毛刺累计；验证未通过时重新计连续3秒，先前已通过的结论不会因一帧异常立即清除。

明显异常不延迟：位置误差达到±1°或速度达到±10°/s就停止；驱动故障、关闭、实测超出配置行程、通信或记录异常、浏览器心跳丢失等原保护仍立即生效。这些数值是本调参工具的保护设置，不是电机物理极限，不下发到驱动器，也不修改PID或ROM。

例如目标159.38°、实测159.38°、速度单帧-4°/s：显示观察，保持原输出；下一帧恢复则继续保持。若-4°/s连续3帧并持续0.5秒，记录“速度持续超限”并停止。页面显示停止前速度、保持峰值速度、观察帧数和持续时间；会话JSON的stop_trigger保存真正触发停止的采样，不用停止后的回位速度解释停止原因。

波动观察中暂不允许切换下一角度，恢复后可继续。手动停止始终可用。软件只根据采样判断，不能保证识别所有高频振动，调试时仍需现场观察。

### 为什么整组读回仍是300，输入框却是400？

例如本次整组设置读到速度300/10/0，操作者填写400/10/0后点击写RAM。0x42成功应答后，本工具保留“已应答目标400/10/0”；如果0x14仍返回300/10/0，会把它作为整组设置读回单独展示。当前固件尚无已确认可用的独立运行RAM读取路径，不能把这两个值不同直接解释为写入失败，也不能把应答成功解释为运行值已经读回。每环的写入详情保留请求、应答、整组读回和提示，供后续核对。

若出现红色“RAM写入未验证”，说明写入流程中断或未取得充分确认，写入可能已生效也可能失败；任一环处于此状态或“ROM保存未确认”时，全局禁止保存、使能和试转。读取整组设置或重新连接不能证明先前写入没有生效，不要据此消除疑问后继续试转。写入超时不自动重发。

## “扭矩不够”的调试顺序

以下是保守的待验证试验顺序，不是保证有效的厂家定值，也不是已替你执行的参数修改。

- 大臂原始：角度50/0/0，速度300/10/0。小臂原始：角度50/0/0，速度500/25/0。负载不同，不能直接照抄小臂参数。
- 保持角度50/0/0、速度Ki=10和Kd=0，先将速度Kp从300试到350。固定目标、负载和速度比较。稳定但仍偏软，再试400，必要时450。不要一步跳到1000或2000。
- 本机现场反馈速度Ki从10增至11就出现抖动，因此先保持Ki=10、Kd=0，不继续加积分。使用现场最后确认不抖的Kp；若600/10仍细抖，可单变量小步退到550、500。Ki=10本身也抖时再考虑9、8，允许残余误差增加，先获得稳定。每步写RAM、检查成功应答，在同一姿态、负载、2°位移和18°/s速度下人工试转；来回找位、振荡或过冲时停止并回退最近修改。
- 若MS输出raw持续接近±850但仍推不动，继续加PID通常不能增加可用输出。先检查卡滞/摩擦、负载和力臂、负载下电压跌落或电源限流，再评估减载、减速机构或电机能力。
- 当前MS输出限制850，不代表850A、850W或850N·m；界面只读，不提高它。MS输出反馈不是MF/MG的转矩电流，母线电流也不能直接当扭矩。
- 先固定18°/s比较PID；之后若需检查速度影响，单独比较18与30°/s，不同时改PID。不要靠不断提高速度绕过机械过载。

## 协议与记录

默认 `hardware.pid_parameter_protocol=vendor_v235`，无需修改 robot.json。

| 操作 | 命令 | 数据 |
|---|---|---|
| 读取整组设置 | 0x14 | 无数据请求；104字节设置应答，总帧110字节；不当作运行RAM的独立读回 |
| 写RAM | 0x42 | ParamID 0x96/0x97 + Kp/Ki/Kd六字节，严格校验参数ID及成功标志；目标单独记录 |
| 保存整组ROM | 0x15 | 最新104字节快照叠加已应答PID目标；保留其他字段，应答后整组核对，持久性待重上电验证 |
| 状态/角度 | 0x9A/0x9C/0x94 | 原项目反馈 |
| 停止/使能/试转 | 0x81/0x88/0xA6 | 显式操作触发，停止保护除外 |

厂家上位机静态代码与两台实机三轮读取共同确认104字节布局：角度PID偏移50、速度56、电流62、输出限制68，末尾有效标志 `78 56 AA 55`。设置中的driverId实测为0，交易地址匹配依据帧头ID1/2。扩展帧解析仅用于调参工具；原 `control/protocol.py` 的100字节限制不变。

另有兼容公开逐项参数协议的驱动，可显式设置 `hardware.pid_parameter_protocol=parameter` 使用0x40/0x42/0x44；当前两台不要使用。写入超时不自动重发。

会话JSON含整组备份、PID、操作日志、失败报文和最近1800个采样；`motion`分别记录运行阶段、试验结论、保持时间、停止原因、起点及误差。CSV含 `iq_or_power_raw`。图表显示最近30秒。故障、试转超时、浏览器心跳丢失、验证超时或保持失败时会尝试停止；停止未确认会保留串口并锁定试转和写入。软件停止依赖通信，不替代物理急停。

## 验证边界

实机已验证0x14读取、数据校验、三轮一致性和隔离期间收发计数。部署验收仅读取；使用中已出现0x42成功应答而0x14仍返回旧值的情况，因此这两条证据分别记录。目前未确认运行RAM的独立读取方式，不能用整组设置读回替代它；保存后的断电持久与实际调参效果仍需现场验证。离线覆盖ACK状态、整组保存字段保留、目标核对和未确认状态的动作限制。
