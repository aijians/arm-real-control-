# 每个途经点的恢复轮次

`motion_recovery.max_recovery_rounds=3`：每个途经点共最多3轮恢复，两轴共用节点轮号。正常首次目标命令不占恢复轮数；首次实际写出恢复指令才进入第1轮。

一轮可包含多次升降档和0.2/0.6/1.2°三个偏置档。`upshifts`、`downshifts`、`angle_changes`只是本轮调节步骤的计数，不分别消耗恢复轮数。完整一轮仍失败并达到无效观察窗上限后，实际写回原名义目标才开始下一轮；写入失败不计入下一轮。最多3轮后结束，不能无限重复。

换途经点重置轮次、步骤计数和恢复截止时间，每点仍受24秒绝对恢复期限限制；整条路径另有有限超时。恢复轮内的小幅进展不重置次数或无限延长期限。普通升档速度下限跨同一单调段保留；90只用于当前节点最后一级，新节点继承普通60下限，避免在90档叠加新偏置。重启下一轮也先将90召回普通上限、写回原目标再调角。

诊断增加`waypoint_index`、`recovery_round`、`max_recovery_rounds`、`total_rounds_started`和`recovery_budget_scope=waypoint`，事件携带节点和轮号。

## 越过节点后的回到原目标

`overshoot_return_enabled=true`，`overshoot_return_speed_deg_s=18`。明确越过当前节点容差后，进入overshoot分支，不因某一帧速度为0就当作卡住。

回调目标永远是当前节点原名义角，不附加偏置。发送前要求新鲜角度和速度、连续至少0.1秒低速且角度变化一致的静止证据、仍在节点容差外，并通过既有恢复目标校验；然后按实际目标差重新确定方向。明确的回调请求允许同一绝对目标变更方向一次，普通指令仍遵守原去重/方向规则。回调期间运动不会直接消耗失败窗口；窗口角度确实静止且仍带外时才判该轮无效。纠正后须在原节点容差内稳定，再推进节点或进行最终保持。

每轮最多一次回调写入，最多共3轮；不成功写入不消耗下一轮。回调和归零偏置在写成功后才提交状态。动态超范围、反馈失联和既有几何/限位拒绝仍可使恢复退出。0x81会释放输出，不能用作持续抱闸；此路径没有引入自动0x81制动。

`test_overshoot_return.py`覆盖5阶段×2轴×2方向、4°构造过冲回调、仍在运动/单零速/过期不反向、无明确回调仍禁止同角改向、回调写失败不假提交、3轮回调无效退出。没有实机成功声明。

诊断增加独立`sent_actions`队列（最多256条）和`dropped_sent_actions`，实际A6帧不会再被大量skipped决策挤掉而不留计数。它记录主机成功write，不是驱动目标寄存器读回。
